# 修订已有译文与翻译新版本

仅在以下情况阅读本文件：目标译文目录已经存在；用户要求修订或勘误已有译文；要翻译同一论文的另一个版本。其余规则仍以 `SKILL.md` 为准。

## 1. 先判断是哪种情况

对照已有译文头部的"原文版本"和当前 PDF 的版本（arXiv ID 及版本号，或会议／期刊及年份）：

| 情况 | 处理 |
| --- | --- |
| 同一版本，已有译文未完成（状态为"翻译中"） | 按第 2 节续译 |
| 同一版本，已有译文已完成，用户要求修订或勘误 | 按第 3 节修订 |
| 同一版本，已有译文已完成，用户没有提出修订 | 不改动，告诉用户译文已存在，询问是否要修订 |
| 不同版本 | 按第 4 节新建译文目录 |
| 无法确认两者是否同一版本 | 停下来向用户确认，不猜 |

"已完成"指原文 Markdown 和译文的状态都已是完成。按旧约定生成的译文目录可能没有原文 Markdown：续译时一并补建；已完成的译文只告诉用户缺少原文文件，询问是否补建，不擅自补建。

## 2. 续译未完成的译文

- 先完整读一遍已有的原文 Markdown 和译文（长文件要读到结尾），弄清两者各自已完成的范围、已有的术语用法和已截取的图表。原文整理进度落后于译文时，先把原文补齐到同一位置。
- 已有内容如果不符合当前翻译口径，要统一修正，例如术语、数量记法、多余的中英对照。不要把风格不同的两部分直接拼在一起。
- 在原来的两个文件里继续整理和翻译，不另建文件。已有内容需要大面积重写时，先向用户说明原因并确认。
- 完成后按 `SKILL.md` 的验收清单检查全文，不能只检查新增的部分。

## 3. 修订已完成的译文

- 直接修改原文件，不另存副本，也不新建目录。勘误源于原文转录错误时（例如抄错数值、漏了一段），原文 Markdown 和译文要一起改，保持两者对应。
- 在被修改文件的头部增加或更新一行 `- 修订日期：YYYY-MM-DD`。状态仍按实际情况填写。
- 重要勘误在被修改文件文末的"修订记录"中简要记录日期与内容，措辞修饰这类小改动不需要记录：

```markdown
## 修订记录

- 2026-10-02：更正表 3 第 2 行的数值，原译文误抄为 0.857。
- 2026-10-02：补译附录 C 的脚注 4。
```

- 需要重新截图时，同名覆盖原文件。修订后不再被引用的图片，先列给用户，确认后再删除。
- 修订后，对改动涉及的章节和图表重新执行验收清单中的相关检查。

## 4. 翻译同一论文的新版本

- 为新版本新建译文目录。旧版本的译文目录和附件原样保留，不覆盖，也不混放附件。
- 有 arXiv ID 时，版本号已经写在目录名里（如 `2510.13999v2 REAP/` 与 `2510.13999v3 REAP/`），自然不会冲突。
- 没有 arXiv ID 时，`<论文简称>/` 可能与旧版本重名。这时不要自己拼接后缀，先向用户确认新目录名。
- 新版本的原文 Markdown 和截图都必须从新版本的 PDF 重新整理、重新截取，不能复用旧版本的文字或图片。
- 旧译文可以作为术语和表达的参考，但内容必须以新版本 PDF 为准逐节核对，不能直接沿用旧版的段落。
