# 学术论文中文全文翻译

输入：一篇论文的 PDF，文件名与所在目录均无要求。

输出：一个译文目录，包含一份完整的原文 Markdown `<原 PDF 文件名主体>.md`、一份完整的中文译文 `<原 PDF 文件名主体>.zh-CN.md`，以及两者共同引用的全部图表截图 `assets/`。

## 所需能力：PDF 区域截图

本 skill 不自带截图工具，需要借助另一个具备以下能力的 skill。开始翻译前，先从当前可用的 skill 中**按能力挑选，不要按名字找**。所需能力：

1. 能把 PDF 页面渲染成图片，供查看和定位；
2. 给定源 PDF、页码、矩形区域和输出文件名，能直接从原 PDF 页面截出 PNG，不重绘、不重新排版；
3. 输出目录和文件名由调用方指定；
4. 截图足够清晰，小字、坐标轴、图例和数值都看得清；
5. 区域超出页面时报错，而不是静默输出空白或残缺的图。

选定后，坐标写法、命令和参数都按那个 skill 自己的说明执行。本 skill 只决定三件事：截哪些对象、每张图的文件名、存到哪个目录（译文目录下的 `assets/`）。

**找不到满足条件的 skill 时，停下来告诉用户**：说明缺哪项能力，请用户安装或启用具备该能力的 skill 后再继续。不要临时写裁剪代码，不要用整页截图代替，也不要先交付不含图表的译文。缺依赖是环境问题，不能靠即兴发挥绕过。

## 翻译口径

读者是熟悉该论文领域的人。**目标是完整、准确、读起来顺畅，而不是把所有内容都中文化。** 正文用自然中文，常见行业术语和数量记法保留原文。

- 用 UTF-8 编码、以简体中文为主的 Markdown。一篇论文的一个确定版本只对应一份完整译文，不按页或按章拆成多个文件，也不逐段重复英文原文（原文单独写在原文 Markdown 中）。
- 按原文顺序完整翻译标题、摘要、各节正文、脚注、图表标题与说明、算法文字、附录、致谢，以及贡献、伦理、局限等其他文字性声明。不删段，不用重点概述代替全文，不能因篇幅长省略附录。
- 保留章节、公式、图表、算法和文献引用的原编号。公式和数学符号按下方"公式与数学符号"书写。代码和伪代码保留结构与标识符，只翻译文字说明和注释。参考文献完整保留原始书目信息，作者姓名、论文原题、DOI 和 URL 不翻译。
- **常见术语直接保留英文**，例如 LLM 论文里的 `benchmark`、`router`。不强行译成中文，不要求首次出现时中英对照，也不反复加括注。同一术语全文保持一致。
- **术语说明只补必要内容**：新定义的、不常见的或容易产生歧义的术语，只在有助理解时补一次简短释义，后文不再重复。原文已有的定义、解释和限定仍须完整翻译，不能因为读者熟悉领域就省略。
- **数量记法沿用原文**，保留数字、字母单位及大小写，如 `100M`、`10B`。不换算成万、亿、万亿，也不并列两种写法。例如写"20B 到 1T"，不写"200 亿（20B）到 1 万亿（1T）"。
- 准确保留数值、单位、比较条件、否定和不确定性。不把作者的推测译成结论，也不把自己的阅读判断混进译文。
- 原文有歧义或疑似错误时，忠实保留，并加简短的"译者注"与原文区分，不静默改写。认不出的内容必须回查原 PDF；仍无法确认时明确标出，不猜写，也不宣称全文已完成。

**截图例外只限图表等对象本体，不能用整页截图代替正文翻译。** 图内标签和表格单元格可以保留原文，但图题、表题、图注、表注和脚注都必须给出完整中文译文。

## 公式与数学符号

所有公式和数学符号都用标准 Markdown 数学语法（LaTeX 写法），符号、上下标、字体和编号与原文一致。

- **行内**：正文中的公式、变量、单个数学符号都写在 `$...$` 里，如 `$x_i$`、`$\mathcal{L}$`、`$O(n^2)$`、`$\alpha \le 0.5$`。`$` 内侧紧贴内容，不留空格。不用 Unicode 字符（`α`、`≤`、`²`）、代码格式或纯文本拼写代替。
- **独立公式**：用 `$$` 包裹，开头和结尾的 `$$` 各自单独占一行，块前后留空行。
- **多行公式**：放在同一个 `$$` 块中，用 `\begin{aligned} ... \end{aligned}` 按 `&` 对齐、`\\` 换行；分段函数用 `\begin{cases} ... \end{cases}`。不把一组多行推导拆成多个 `$$` 块。
- **编号**：原文带编号的独立公式在块内用 `\tag{N}` 保留原编号，正文引用写"式 (N)"。
- 不用 `\(...\)`、`\[...\]` 定界符，不用代码块或截图代替公式。正文里表示货币的美元符号写成 `\$`，避免被识别为公式。表格单元格内的公式用 `\vert`、`\mid` 代替 `|`。

```markdown
损失函数 $\mathcal{L}$ 由两部分组成，其中 $\lambda > 0$ 为权重：

$$
\begin{aligned}
\mathcal{L} &= \mathcal{L}_{\text{task}} + \lambda \mathcal{L}_{\text{aux}} \\
&= -\sum_{i=1}^{N} \log p_\theta(y_i \mid x_i) + \lambda \lVert \theta \rVert_2^2
\end{aligned}
\tag{3}
$$
```

## 输出组织与命名

| 对象 | 规则 |
| --- | --- |
| 译文目录位置 | 默认建在原 PDF 所在目录下；用户指定了输出位置时，以用户为准 |
| 译文目录名 | 能从 PDF 中确认 arXiv ID 时用 `<arXiv ID及版本号> <论文简称>/`，如 `2510.13999v3 REAP/`；否则用 `<论文简称>/`，如 `MoE-SVD/` |
| 原文 Markdown | **`<原 PDF 文件名（不含 .pdf）>.md`** |
| 中文译文 | **`<原 PDF 文件名（不含 .pdf）>.zh-CN.md`** |
| 附件目录 | 译文目录内的 `assets/` |

- **arXiv ID 以 PDF 内容为准**，例如首页页边的 arXiv 标识。文件名只能当线索，不能凭文件名或记忆推定。
- **论文简称**取论文自己使用的方法名或模型名，如 `REAP`、`MoBE`；没有的话，从标题里取简短关键词。简称要简短稳定，不能含路径非法字符 `\ / : * ? " < > |`。中文标题和完整英文标题写进译文内，不放进目录名。
- **两个文件名都只去掉原文件名末尾的 `.pdf`，原文再加 `.md`，译文再加 `.zh-CN.md`。** 原文件名主体的大小写、空格、标点和版本号全部保留，不改成中文标题，不缩写成简称，也不统一叫 `zh-CN.md`、`original.md`，原文文件名也不加 `.en` 等语言后缀。如果遇到 Windows 长路径限制，先处理路径支持或向用户确认，不能擅自缩短文件名。
- `assets/` 只放原文或译文引用到的图片，两个文件共用同一组截图，不各截一套；以及截图工具在其中生成的非图片记录文件（保留原样，不手工修改）。截图工具的工作目录、页面预览图、提取文本等中间材料不放进译文目录。
- 原 PDF 不移动、不改名、不修改，也不复制进译文目录。
- 目标目录已存在时，先读 `references/revising.md`，不直接覆盖。

示例（PDF 位置和文件名可以是任意的）：

```text
some/dir/
├── 2510.13999v3 REAP the Experts- Why Pruning Prevails for One-Shot MoE compression.pdf
└── 2510.13999v3 REAP/
    ├── 2510.13999v3 REAP the Experts- Why Pruning Prevails for One-Shot MoE compression.md
    ├── 2510.13999v3 REAP the Experts- Why Pruning Prevails for One-Shot MoE compression.zh-CN.md
    └── assets/
        ├── fig-01.png
        ├── table-01.png
        ├── fig-a05.png
        └── （截图工具生成的记录文件）
```

## 图表截图

- 从同一版本的原 PDF 截取，每次截取完整对象，小字、坐标轴、图例和数值都要清晰。不重绘，也不为了转格式重新排版图表。
- 截图范围只包括对象本体，默认不含原文图题和图注；它们以文字形式写在截图旁边：原文 Markdown 写原文，译文写中文译文。
- 文件用 PNG，按原文编号命名：`fig-01.png`、`table-02.png`；附录图 A.1 记为 `fig-a01.png`，正文里显示的仍是原编号。拆分的子图用 `fig-02-a.png`；跨页的表依次用 `table-03-part-01.png`、`table-03-part-02.png`。无编号对象用 `image-p005-01.png`，表示原 PDF 第 5 页的第 1 个无编号对象。
- 每个图表放在原文对应的位置，截图本体与中文标题、说明相邻，不能全部堆到文末。截图里即使带有英文图注，也不能省略中文图注。
- 附件只用包内相对路径引用，路径分隔符用 `/`。不用机器绝对路径、临时路径或远程图片链接。

```markdown
![图 1：中文图题](assets/fig-01.png)

**图 1｜中文图题**（原 PDF 第 4 页）
完整的中文图注，包括原图注中的条件、缩写解释与补充说明。
```

表格同样使用这个格式，把"图 N"换成"表 N"即可。原文 Markdown 用同样的结构，图题和图注照录原文，例如 `**Figure 1 | Original caption title** (PDF p. 4)`。

## 译文头部与原文对照

译文开头记录以下信息。日期格式为 `YYYY-MM-DD`（UTC+8）；状态只有两种写法："翻译中（注明已完成范围）"或"已完成全文翻译与核对"。

```markdown
# <中文标题>

- 英文原题：<Original Title>
- 作者：<作者>
- 原文版本：<arXiv 2510.13999v3，或会议／期刊及年份>
- 在线原文：<https://arxiv.org/pdf/2510.13999v3>
- 本地 PDF：[原始 PDF](<../原 PDF 文件名.pdf>)
- 翻译日期：<YYYY-MM-DD>
- 状态：<翻译中（已完成：……）｜已完成全文翻译与核对>
```

- **在线原文**：有 arXiv ID 时用 `https://arxiv.org/pdf/<ID及版本号>`。没有时，用 PDF 中给出的 DOI 或论文集链接；确认不了就写"未确认"，不猜。
- **本地 PDF**：写从译文文件到原 PDF 的相对路径，默认是 `../<原文件名>.pdf`。路径含空格时用尖括号包裹。无法构成相对路径时（例如不在同一个磁盘上），只写原 PDF 文件名。
- **原 PDF 页码**一律指从第 1 页开始的文件页序，不是论文上印的页码。在章节起始处和图表旁简短标注，方便对照，不需要每段都标。
- 以明确选定的这份 PDF 为翻译依据。提取工具或 HTML 只能辅助，必须核对版本与内容，不能混用其他版本，也不能只凭摘要补全文。

## 原文 Markdown

原文 Markdown 是这份 PDF 正文的完整、忠实转录，用于对照阅读，也是翻译的底稿。

- **内容范围与译文一致**：标题、摘要、各节正文、脚注、图表标题与说明、算法、附录、致谢、声明和参考文献全部照录，不删减、不概括、不改写、不纠错。原文的拼写错误或疑似错误原样保留，需要说明时只在译文中加"译者注"。
- **结构与译文一一对应**：章节标题层级、段落顺序、公式、图表位置和原 PDF 页码标注都与译文相同，方便逐段对照。图表引用同一个 `assets/` 下的同一张截图。
- **排版只做必要清理**：去掉页眉、页脚、页码和行号，合并跨行、跨页断开的段落和连字符断词。公式和数学符号按"公式与数学符号"书写，脚注、代码和伪代码保留原样。
- **头部**沿用译文头部的格式，但第一行用原题，去掉"英文原题"一行，日期写"整理日期"，状态写"整理中（注明已完成范围）"或"已完成原文整理与核对"：

```markdown
# <Original Title>

- 作者：<作者>
- 原文版本：<arXiv 2510.13999v3，或会议／期刊及年份>
- 在线原文：<https://arxiv.org/pdf/2510.13999v3>
- 本地 PDF：[原始 PDF](<../原 PDF 文件名.pdf>)
- 整理日期：<YYYY-MM-DD>
- 状态：<整理中（已完成：……）｜已完成原文整理与核对>
```

## Workflow

1. **检查截图能力**：按上文"所需能力"挑选截图 skill，找不到就停下来告诉用户。
2. **锁定源与版本**：读 PDF 首页和元数据，确认标题、作者、版本（arXiv ID 及版本号，或会议／期刊及年份）和总页数。
3. **确定译文目录与文件名**：按"输出组织与命名"确定。目标目录已存在时，读 `references/revising.md`。
4. **列结构清单**：通读全文，列出各节、附录、脚注、图、表、算法和参考文献及其所在页码，作为翻译和自检的依据。提取出的文本只作辅助，阅读顺序、公式、上下标都要对照页面核对，全部内容都要读到。
5. **截图**：用选定的截图 skill，把清单中每个图表对象按命名规则截到 `assets/`，然后逐张查看，确认完整、清晰、没有混入邻近正文。
6. **整理原文**：按"原文 Markdown"写入原文文件，头部状态先写"整理中"，逐节对照页面核对文字、公式和上下标。篇幅长时分批追加到同一个文件。
7. **翻译**：以核对过的原文 Markdown 为底稿，按原文顺序写入唯一的译文文件，头部状态先写"翻译中"；有疑问时回查原 PDF。篇幅长时分批追加到同一个文件，不另建分章文件，也不能因为篇幅长改写成提纲。
8. **自检**：按下方验收清单逐节对照原 PDF 检查两份文件，发现问题当场修正。
9. **交付**：自检通过后，把两份文件的状态分别改为"已完成原文整理与核对"和"已完成全文翻译与核对"，并向用户报告两份文件的路径、页数、图表数量和未解决的问题。没有完成就如实写明已完成的范围。单独分享时要把整个译文目录一起交付，不能只发 `.md` 却说图片可用。

## 验收清单

- 正文、附录、脚注、图表说明和参考文献都没有遗漏；没有用摘要或截图替代应翻译的文字。
- 正文自然顺畅；常见术语保留英文且用法一致，没有多余的中英对照；数量记法与原文一致，没有换算或重复表示。
- 数值、公式、术语、编号和引用都与原文一致；没有添加原文未声称的结论。
- 公式和数学符号全部使用 `$...$`／`$$...$$`，没有 Unicode 数学字符或纯文本公式，带编号的公式保留了 `\tag{N}`。
- 原文 Markdown 完整照录 PDF 全部文字，没有遗漏、改写或纠错；章节、段落、公式和图表位置与译文一一对应。
- 原文和译文的文件名严格等于原 PDF 文件名主体分别加 `.md` 和 `.zh-CN.md`。
- 图片引用都是 `assets/` 下的相对路径且文件存在；每张截图清晰、完整、位置正确；`assets/` 中没有两份文件都未引用的图片。
- 头部的版本信息、在线链接和本地链接准确；未完成的内容如实标注，没有把中间稿当作完整译文交付。

## 边界

- 只负责整理原文、翻译与交付译文目录。不提交、不推送 git；不移动、删除原始资料，除非用户另行要求。
- 仅在以下情况读 `references/revising.md`：目标译文目录已存在；用户要求修订或勘误已有译文；要翻译同一论文的另一个版本。
